CODEX BUILD PROMPT: Offline Expressive Voice Studio
Build a working compact cross-platform expressive TTS desktop application. Implement all requested feature families in the first complete release, using tested incremental milestones, not mockups. Use Rust + Tauri for desktop UI and orchestration; prefer ONNX Runtime for compatible lightweight engines. Optional engines may require isolated, separately downloaded runtimes. Never claim every TTS model can be run natively in Rust.
Product
- Windows x64 installer and portable edition; macOS Intel x64 and Apple Silicon arm64; Linux x64 package/AppImage. Low-power Apple Silicon and old Intel machines must have a CPU fallback where supported. Build/test on each architecture before claiming compatibility.
- Aim for 10–20 MB installer excluding models/runtime dependencies; measure actual size. All models optional, downloadable and removable in Options > Models. Download manager: destination picker, integrity verification, resume where supported, storage estimates, model import, compatibility and license metadata. After downloading, all generation works offline.
- Almost no CPU/GPU activity at idle: no models loaded until MAKE; inference in a cancellable background worker, bounded RAM/VRAM, one job by default, automatic device selection with CPU fallback. GPU acceleration only when genuinely supported. Avoid UI freezes and orphaned processes.
- Main window: text editor, always-visible emotion markup legend, voice selector, three toggles Emotion Control / Voice Clone / Batch Mode, big MAKE button, progress/cancel, and Winamp-like output playlist (play/seek/replay/rename/search/reveal/export). Simple and Advanced modes; Simple Mode still includes the legend and all essential functionality.
Exact text markup legend
- "text" = excited / high-energy delivery.
- [text] = calm / restrained delivery.
- {text} = mystery / suspense.
- *text* = emphasis.
- -- = short pause.
- --- = long pause.
- Untagged = neutral.
The legend is displayed directly above the editor; clicking an entry wraps selected text. Parse deterministically, preserving all spoken words in exact order. Never pronounce control characters. Test nested/unbalanced markup, literal quotes, escapes, Unicode, empty spans, punctuation and timing. Advanced mode can change pause lengths and inspect segment boundaries. Use genuine emotion/style controls only for models that support them; otherwise label rate/pause/prosody approximations. Kokoro alone does not guarantee genuine excitement.
Voice reference
Import approximately 30–60 seconds of user-authorized reference WAV/MP3; trim, preview, validate quality, save as named reusable voice profile. Two switches/modes: Voice Only (speaker identity; script markup controls delivery) and Voice + Style (attempt speaker identity plus reference energy/cadence). Only enable when selected engine genuinely supports the requested conditioning; do not fake identity/style separation. Never promise exact voice matching. Include a rights/consent reminder.
Engines and models
Start with a real Kokoro ONNX integration for lightweight English TTS. Evaluate F5-TTS, Chatterbox, and other license-compatible models for actual reference voice cloning and emotional delivery. They may need optional Python-based workers; isolate these, download on demand, and verify Windows/macOS/Linux compatibility. Provide a catalog capable of listing about 20 evaluated models, but do not fabricate scores or integrations. Show measured speed, naturalness, expressive control, cloning ability, model size, RAM/VRAM, languages, supported hardware, source, license and commercial-use conditions. Unsupported = visibly unsupported.
Production workflow
Paste tagged English Shorts narration or longer scripts; click MAKE; render sequential segments with stable identity and suitable emotion; use small fades, pause insertion, loudness normalization, and click-free stitching; export WAV, optionally MP3 if properly supported. Save project metadata, script, settings, reference, segments and final file in searchable project folders. Batch 20+ scripts with persistent queue, cancel, resume and retry. Cache unchanged segments and invalidate cache by text/model/voice/settings hash. User-selected output folder and model folder; retain models after app updates.
Quality and verification
Use versioned schemas, safe paths, checksums, atomic writes, download recovery, offline operation, crash isolation, no cloud account, accessible keyboard UI and diagnostics. Test idle RAM/CPU, cold start, real-time factor, peak RAM/VRAM, 60-second narration, voice stability, emotion tag behavior, batch restart, model absence, interrupted downloads, corrupt audio and unsupported device. Document benchmarks honestly. Deliver source, build steps, CI, release artifacts when possible, licenses, tests and example scripts. Do not stop at planning/scaffolding: demonstrate real playable audio and voice-cloned output from an authorized reference on a supported backend.
